# Design

## Decisions

- **State in `.github/workflows/pr-title-caller.yml` that its job sets no concurrency key, and hold the removal of the reusable workflow job concurrency group in dan-petty/github-workflows.**: The probes report the reusable workflow as no file of the staging commit and commit f1067fd as the commit that deleted or renamed it, so the group that leaves the cancelled check run is a line of the workflow of dan-petty/github-workflows, and the caller is the only PR title workflow file that infra holds.
- **Add the guard test under `tests/` beside the caller it reads, and run it in the job `actionlint` of `ci.yml`.**: The tests of the repository are shell scripts that read a workflow with the yq of `mise.toml`, as `tests/test-ci-check-names.sh` does, and the job `actionlint` installs yq and runs that test.
- **Give each group a check by hand instead of a `uv run devops` verify.**: `uv run devops ci docs` checks the documents of devops-cli, not the files of infra, and the checks of this change are `mise exec -- actionlint` and `mise exec -- tests/test-pr-title-no-concurrency.sh`, which no verify form of the plan accepts.
- **Keep the workflow-level concurrency of `.github/workflows/ci.yml`.**: `.github/workflows/ci.yml:19:group: ci-${{ github.ref }}` keys the group on the ref, and the issue names the job concurrency of the title check, not the group of the CI workflow.
- **Leave the fixture caller `tests/renovate/.github/workflows/pr-title.yml` and the spec `openspec/specs/pr-title-scopes/spec.md` unchanged.**: The fixture is the caller that the repository template of dan-petty/github-workflows renders for the Renovate preset test, it sets no concurrency key and it never runs; the spec of `pr-title-scopes` states the scopes of the title check and holds no concurrency rule.
- **Change no behavior that a consumer observes, so the change carries no spec delta.**: Every path of `changes` is a workflow file, a test file or a document, and no requirement of a capability changes: the workflow comment states an invariant and the guard test reads a file.

## Rejected alternatives

- **Remove the job concurrency block of the reusable PR title workflow in this repository, as the issue proposes.**: The probes report: "The path `.github/workflows/pr-title.yml` is no file at the root of the staging commit." and "Commit f1067fd 2026-11-27 feat: call the workflows of github-workflows (#235) deleted or renamed it."
- **Set `cancel-in-progress: false` on the group.**: The tool `search_code` for `concurrency` on the staged commit returns only `.github/workflows/ci.yml:18:concurrency:` and two lines of an archived design document, so the staged tree holds no title workflow group to set; the issue body states that GitHub also cancels a run that waits in a group.
- **Copy the reusable workflow into infra and remove the group here.**: `.github/workflows/pr-title-caller.yml:19:` `@39f92fb644e550f84a5797cce46a80a891231d4a # v0.1.0` shows that infra calls the workflow of dan-petty/github-workflows at the commit of a release tag, so a copy would drift from that release.
- **Filter the cancelled check run in the Renovate presets of infra.**: The issue body states that Renovate merges only when each check run is `success`, `neutral` or `skipped`, so a cancelled check run still stops the merge.
- **Add an actionlint or a zizmor rule that refuses a job-level concurrency key.**: The alternatives block of the issue body records the verdict `none` and no tool for this need, and the tool it considered is actionlint, pinned at `mise.toml:8:actionlint = "1.7.12"`.
- **Write one guard over each workflow file of `.github/workflows/`.**: The tool `list_files` of `.github/workflows` gives three files, and the issue names the title check, so the guard reads `.github/workflows/pr-title-caller.yml`; `.github/workflows/ci.yml:18:concurrency:` keeps its workflow-level group keyed on the ref, and `.github/workflows/release-caller.yml` runs once per push to main.
