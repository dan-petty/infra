# Design

## Decisions

- **Name the Pages site as a `pages` object with the fields `build_type`, `source`, `cname` and `https_enforced`.**: The object names each field of the Pages request body, and `additionalProperties: false` refuses a misspelled field, as the rest of `templates/github-repository.schema.json` does. `source` holds a `branch` and a `path` of `/` or `/docs`, the two paths of the Pages endpoint, and the schema requires `source` when `build_type` is `legacy`, because a legacy build reads its files from that branch and path. `cname` is a string or null, because the update endpoint of the site removes the custom domain on null, and the live site of dan-petty/devops-cli answers `cname: null`.
- **Name the collaborators as an array of objects with a required `username` and a required `permission` of `pull`, `triage`, `moderate`, `push`, `maintain` or `admin`.**: An array validates each item and keeps the order of the answer, and the enum is the list of permissions that the documentation of the collaborator endpoint of the GitHub REST API gives. The same documentation says that `permission` is "Only valid on organization-owned repositories": on a repository that a user owns, such as each repository of dan-petty, GitHub grants `push` for each answer. The README row says so.
- **Ask for the site with a `pages` answer that defaults to false, and render `pages: { build_type: workflow }`.**: Not every repository publishes a site, so a default render holds no `pages` key, and the build type `workflow` publishes the site from a workflow of the repository, as the live site of dan-petty/devops-cli does.
- **Ask for the collaborators as a comma-separated `username:permission` answer with default empty, validate each pair in `copier.yml`, and render no `collaborators` key for an empty answer.**: Copier refuses a pair with an unknown permission before the render, so no invalid collaborator reaches the settings baseline. A key that is absent names no collaborator set. dan-petty/devops-cli#5325 plans a collaborator row that removes each live collaborator that the baseline does not name, so an empty list would ask that row to remove each collaborator of the repository.
- **Render the environment `github-pages` with `protected_branches: false`, `custom_branch_policies: true` and the branch policy `main`, and render `environments` when `release_flow` or `pages` is true.**: Only `main` deploys the site, which is the policy of the live environment `github-pages` of dan-petty/devops-cli, and a repository with no release flow and no site keeps no `environments` key, which the case at `tests/test-repository-template.sh:140:expect "defaults: no environment" "0" \` asserts. Row 5 of `devops repos onboard` writes each item of `environments`, so it applies `github-pages` with no change of the command.
- **Keep the exact Pages and collaborator values of dan-petty/devops-cli out of this repository, and leave that render to #188.**: The values are the answers of one repository, and `scripts/private-data-scan.sh` refuses a private value in this repository. dan-petty/devops-cli has no `.copier-answers.yml` yet: the first run of `devops repos onboard` writes it with the answers of its flags, and the command has no flag for `pages` or `collaborators`. So a person gives the two answers after that render with `copier update --data`, which the onboard document of devops-cli names for each change of an answer.
- **Check the change with the commands of README.md, "Checks".**: `mise exec -- tests/test-repository-template.sh` is the command of the CI job `template`. `uv run devops ci --check --only template` exits 2 with `Unknown check row`, because `devops ci` runs the rows of devops-cli only.

## Rejected alternatives

- **A boolean `pages` key.**: It cannot name the build type or the source, and `templates/github-repository.schema.json` holds an object for each endpoint, such as `code_scanning_default_setup`, so a boolean breaks the shape of the file.
- **A free-form object for `pages`.**: `templates/github-repository.schema.json` sets `additionalProperties: false` on each object, so a misspelled `buildtype` fails; a free-form object would accept it.
- **A map of username to permission for the collaborators.**: A JSON Schema map cannot require a permission for each key or name the item that fails; the array of objects gives the failing index, and the validator of `copier.yml` refuses the answer before the render.
- **An empty `collaborators` list for an empty answer.**: An empty list names an empty set, and the collaborator row that dan-petty/devops-cli#5325 plans removes each live collaborator that the baseline does not name.
- **The five permissions of the issue, with no `moderate`.**: The documentation of the collaborator endpoint lists `moderate` too, and the schema takes its allowed values from the API.
- **A hardcoded Pages site or collaborator in the template.**: `scripts/private-data-scan.sh` and `tests/test-private-data-scan.sh` refuse a private value in the repository, and one hardcoded value would give every render the settings of one repository.
- **The `protected_branches` policy of the environment, or no policy at all.**: `templates/github-repository.schema.json` holds both `protected_branches` and `custom_branch_policies`; the protected policy admits each protected branch and no policy admits any branch, while the custom policy names `main` alone.
- **`uv run devops ci --check --only template` as the check.**: It exits 2 with `Unknown check row: 'template'`, so it fails on the base and after the change.
