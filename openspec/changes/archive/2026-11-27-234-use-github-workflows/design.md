# Design

## Decisions
- **infra calls `k8s-validate.yml` of dan-petty/github-workflows for its own templates.** The workflow takes each input that `ci.yml` gives (`kustomize-roots`, `helm-charts`, `promtool-rules`, `kube-linter-ignorefile`, `trivy-ignorefile`), checks out its own commit (`job.workflow_sha`) for the script, the shared `.kube-linter.yaml` and the tool pins, and the script differs from the old script of infra only in comments and the name of one variable. So infra keeps no copy of the script, of `.kube-linter.yaml` or of their tests: dan-petty/github-workflows tests them (`tests/test-k8s-validate.sh`, `tests/test-kube-linter-config.sh` there). The job `K8s` still reports the result of the call, so `tests/test-ci-check-names.sh` and the required check `K8s` stay.
- **The judgments of infra stay in `helm/.trivyignore.yaml` and `helm/.kubelinterignore.yaml`.** The K8s run applies them to the real renders. The deleted cases of `tests/test-k8s-validate.sh` that held the entries of these files (finding IDs and object names) were tests of the values of a file, which devops-cli#7229 removed as a class. The test of dan-petty/github-workflows checks that an entry admits only its finding on its object.
- **`tests/test-service-repos.sh` runs kubeconform itself.** It called the deleted script only for its kubeconform step. The test gives kubeconform the same two schema locations: the default and the CRDs catalog of datreeio.
- **infra holds no render of the template.** Its callers keep the file names `pr-title-caller.yml` and `release-caller.yml`, so the rule of #225, which matches `.github/workflows/pr-title.yml` and `.github/workflows/release.yml`, leaves them to Renovate, and Renovate moves their pins. The job names `PR title` and `Release` keep the check names `PR title / Semantic PR title` and `Release / Release Please`.
- **Renovate leaves each caller and each copier render of infra alone.** A release of infra after this change holds no workflow and no template. A caller at that tag calls a workflow that does not exist, and `copier update` to that tag exits 0 after it writes the files of the root of infra into the repository (Copier 9.19.1). dan-petty/homelab (`.github/workflows/k8s.yml`) and dan-petty/danielpetty.com (`.github/workflows/ci.yml`) call `k8s-validate.yml` of infra, and seven repositories hold `.copier-answers.yml` of infra. One rule matches the managers github-actions and copier and each form of the name of infra, with no file condition, so it covers the callers of the template and each other caller.
- **The title rules of dan-petty/github-workflows follow those of infra.** Each form of the name gets the topic `dan-petty/github-workflows`, and the copier update gets `dan-petty/github-workflows template`. The longest summary, `update dan-petty/github-workflows template to v0.10.10`, has 54 characters, within the 60 of the title check.
- **No group for the callers of dan-petty/github-workflows.** Renovate already puts the pins of one dependency at one new release into one branch. The copier update stays on its own branch (#216).
- **Copier and check-jsonschema leave `pyproject.toml`.** Only the deleted template test used them. pre-commit stays for the hooks of infra. `mise.toml` keeps each tool: the local command of the K8s job runs the script of dan-petty/github-workflows with the tools of infra.
- **`.github/zizmor.yml` goes.** Its one rule allowed the form `./...` of a local call, and no local call remains. zizmor 1.33.1 reports no finding without it.
- **The specs of the moved files leave with them.** dan-petty/github-workflows `v0.1.0` holds `template-file-owners`, `template-workflow-pins`, `reusable-workflow-runner`, `pr-title-scopes` and `ci-check-names`. infra deletes the first three, keeps `ci-check-names` for its own `ci.yml`, and keeps only its scope labels in `pr-title-scopes`.

## Rejected alternatives
- **Keep `scripts/k8s-validate.sh` in infra for the local run and the tests.** Two copies of one script drift, and each fix must land two times. The reusable call covers each input of infra.
- **Check out dan-petty/github-workflows in the job `K8s templates` to keep the judgment cases.** The commit would then be pinned in two places of `ci.yml`: Renovate moves the `uses:` line but not a `ref:` input of `actions/checkout`.
- **Make infra a render of the template (a `.copier-answers.yml` of dan-petty/github-workflows).** The template owns `release-please-config.json` and renders `"packages": {".": {}}`, so each copier update would drop the `extra-files` of infra (`ansible/galaxy.yml`, `k8s/bases/service-repos/applicationsets.yaml`). The renders of `.github/labels.yml` and `github/repository.yaml` would also replace the files of infra. #225 decided that infra holds no `.copier-answers.yml`.
- **Name the callers of infra `pr-title.yml` and `release.yml`.** The rule of #225 would then turn off Renovate for them, and no copier update moves them in infra.
- **Keep `dan-petty/infra` in the rule of #225.** The new rule of infra matches each file, so a second rule for two of the files adds nothing.
- **`allowedVersions` up to the last release of infra that holds the workflows and the template.** That version is not known before the merge, and each consumer would get one more pin pull request before its move.
- **Keep the jobs `Repository template` and `kube-linter config` with no work, for the ruleset.** A job that checks nothing hides a removed check. A person removes the two required checks from the ruleset.
