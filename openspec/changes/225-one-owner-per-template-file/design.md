# Design

## Decisions
- **The template owns each file that it renders, except five.** `.github/labels.yml`, `.github/CODEOWNERS`, `github/repository.yaml`, `openspec/config.yaml`, the release-please config and the callers come from the answers. A repository changes them through an answer (`scopes`, `code_owner`, `required_checks`) or through the template. Copier then renders the same text that the repository holds, and `copier update` has nothing to merge.
- **`_skip_if_exists` for the files of the repository.** `.github/renovate.json`, `.pre-commit-config.yaml` and `.devops/project.toml` hold the rules of each repository (dan-petty/homelab: 159 lines of Renovate rules), and release-please writes `version.txt` and `.release-please-manifest.json`. Copier 9.19.1 keeps such a file on `copier update` and on `copier recopy --overwrite`.
- **Turn off the github-actions manager for the template callers only.** The rule matches the manager, the two file names that the template renders and the package `dan-petty/infra`, so the caller of `k8s-validate.yml` in dan-petty/homelab and dan-petty/danielpetty.com keeps its updates in the group `infra` of `renovate/k8s.json`, and an action in another workflow keeps its updates.
- **One copier branch.** `separateMajorMinor: false` puts each new release into the bucket `latest`, so Renovate proposes only the newest release. `separateMinorPatch: false` keeps the branch name at `<dep>-<major>.x` for a patch update too.
- **The title check is a required check of the template.** The template renders `.github/workflows/pr-title.yml` in each repository, and that check reports on each pull request into `main`. The answer `required_checks` lists the other checks, and the template renders them before the title check, the order of dan-petty/homelab. Integration 15368 (GitHub Actions) on each check keeps another app from reporting it. The answer is a comma-separated text, as `scopes`, so `devops repos onboard` passes it to `copier copy --data` as it is.
- **infra is not a consumer of its own template.** Its root files are the template source and its own settings, which a person keeps.

## Rejected alternatives
- **Renovate and `copier update` both write the callers, with one text (#214).** The pull request that merges second needs the same release on both sides. A copier update to `v0.25.2` over callers that Renovate moved to `v0.24.3` conflicts (dan-petty/dreamscaper#33).
- **Hand-made merge or a script that drops the pins before `copier update`.** It builds what `_skip_if_exists` and a package rule already give, against the owner's direction of 2026-11-27.
- **`ignorePaths` for the two callers.** It turns off each manager for the whole file, also for an action that a repository adds to its own `pr-title.yml` (dan-petty/devtools).
- **`_skip_if_exists` for `.github/labels.yml` and `github/repository.yaml`.** The template then never updates them, and their answers (`scopes`, `code_coverage`, `release_flow`) stop working after the first copy.
- **A YAML list for `required_checks`.** `devops repos onboard` passes each answer as `--data <key>=<str(value)>`, which writes a Python list, not YAML, for a list with a quote in a name; a text answer has no such case.
